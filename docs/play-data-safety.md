# Google Play Data Safety worksheet — Sorlio

Answers derived from what the code actually does, not from what the app
intends. Each row names the source file so a claim can be re-checked when the
code changes. Fill the Play Console form (**App content → Data safety**) from
this; if an answer here and the code ever disagree, the code is right and this
file is stale.

> **VERIFY CURRENT GOOGLE PLAY REQUIREMENT.** The Data safety form's
> categories, wording, and required declarations change over time. Treat the
> category names below as a guide to *which* Play category each piece of data
> falls into, and read the current labels in Play Console before submitting.

## Summary answers

| Question | Answer | Why |
| --- | --- | --- |
| Does the app collect or share any user data? | **Yes** | Optional account, optional analytics, feedback, purchases. |
| Is all data encrypted in transit? | **Yes** | Every destination is HTTPS-only: Supabase, Vercel, OpenAI, Resend, Sentry. No plaintext endpoint exists in the code. |
| Do you provide a way to request data deletion? | **Yes** | In-app (Settings → account card → delete) and on the web at `/account/delete`, which signs in and deletes without needing the app installed. |
| Is data collection required to use the app? | **No** | The app is fully usable as a guest; no account, no analytics. See `src/lib/access/accessModel.ts`. |
| Does the app contain ads? | **No** | No ad SDK, no ad identifier, no advertising ID access anywhere in the tree. |
| Is the data used for tracking across apps/websites? | **No** | The anonymous ID is generated by the app for itself and is never shared. |

## Data types collected

### Personal info → Email address
- **Collected:** Yes. **Shared:** No. **Optional** (only if the reader signs in).
- **Purpose:** Account management, app functionality.
- **What and where:** Google OAuth via Supabase. Only the account identifier and
  email are stored — no password ever exists, and no name or profile picture is
  requested or kept. `src/lib/supabase/auth.ts`, `src/app/api/account/delete/route.ts`.
- Also collected separately, and only if the Android beta CTA flag is enabled,
  by the beta mailing list (`sorlio_android_beta_interest`). **That flag now
  defaults to false**, so a standard production build does not collect this.
  `src/lib/validation/config.ts`.

### Financial info → Purchase history
- **Collected:** Yes. **Shared:** No. **Required** for Premium only.
- **Purpose:** App functionality (entitlement), fraud prevention.
- **What and where:** Google Play product ID, purchase token, subscription
  status, and expiry. Sorlio never sees a card number — Google Play processes
  payment and Sorlio only verifies the resulting token server-side.
  `src/lib/premium/googlePlay.ts`, `src/lib/premium/server.ts`.

### App activity → Other user-generated content
- **Collected:** Yes (only when signed in). **Shared:** No. **Optional.**
- **Purpose:** App functionality (cross-device sync).
- **What and where:** Saved words, known words, reading progress and history,
  goals, settings, imported or custom texts. Stored locally first; synced to
  `sorlio_user_data` only for a signed-in user. A guest's data never leaves the
  device. `src/lib/supabase/sync.ts`, `src/lib/storage.ts`.
- Free-text the reader chooses to send: feedback comments (`sorlio_feedback`) and
  research-prompt answers (`sorlio_research_prompt_responses`).

### App activity → App interactions
- **Collected:** Yes. **Shared:** No. **Optional — consent-gated.**
- **Purpose:** Analytics.
- **What and where:** Screen path, event name, a random anonymous ID, a session
  ID, device category (phone/tablet/desktop), whether running as an installed
  PWA, acquisition source/medium/campaign, a returning-reader flag, self-reported
  French level, app version, deployment environment.
- **Nothing is sent before consent.** `trackEvent` returns immediately unless
  `hasAnalyticsConsent()` is true. `src/lib/analytics/client.ts`,
  `src/lib/privacy/analyticsConsent.ts`.
- A hard deny-list rejects any payload carrying article bodies, imported or
  personal text, sentences, translations, AI responses, email addresses, or
  comments; strings are also capped at 500 characters.
  `BANNED_KEYS` in `src/lib/analytics/events.ts`.

### App activity → App interactions (AI usage counter)
- **Collected:** Yes, for Premium subscribers only. **Shared:** No.
- **Purpose:** Fraud prevention, security — an anti-abuse ceiling on paid AI
  features.
- **What and where:** A per-day count of AI calls per account, and nothing
  else — no prompt text, no responses, no article content. `sorlio_ai_usage`,
  written only through `sorlio_consume_ai_call()`. Cascades on account
  deletion. `supabase/migrations/0008_ai_usage.sql`, `src/lib/ai/guard.ts`.

### App info and performance → Crash logs / Diagnostics
- **Collected:** Only if a Sentry DSN is configured. **Shared:** With Sentry as
  processor. **Optional.**
- **Purpose:** Crash reporting, diagnostics.
- If `NEXT_PUBLIC_SENTRY_DSN` is unset, `Sentry.init` no-ops and nothing is
  sent. **Decide before submitting** whether the release build sets it, and
  declare this row accordingly — this is the one row whose correct answer
  depends on your deployment configuration rather than on the code alone.

## Data types explicitly NOT collected

Confirmed by absence from the tree, not by assumption. No code path touches any
of these APIs:

- Location (precise or approximate) — no `geolocation` usage.
- Contacts, calendar, SMS, call logs.
- Photos, videos, audio, microphone, camera — no `getUserMedia`.
- Health, fitness, or biometric data.
- Files and docs from the device — imported text is typed or pasted by the
  reader, never read from storage.
- Device or advertising identifiers. The anonymous analytics ID is generated by
  the app, stored in localStorage, and reset by clearing storage.
- Passwords. Sign-in is Google OAuth only; no password field exists anywhere.

## Android permissions declared

**None.** `android/app/src/main/AndroidManifest.xml` declares no
`uses-permission` of its own. `POST_NOTIFICATIONS` was removed because nothing
in the app has ever sent a notification.

`INTERNET` is contributed by the AndroidX browser-helper library during manifest
merge, which is expected for a Trusted Web Activity and needs no declaration
here.

> **VERIFY** after the first build: run
> `./gradlew :app:processReleaseManifest` and read
> `android/app/build/intermediates/merged_manifests/release/AndroidManifest.xml`
> to confirm the merged result contains only `INTERNET` and nothing that would
> trigger a sensitive-permission declaration form.

## Deletion flow — what actually gets deleted

Play requires that advertised deletion is real. `src/app/api/account/delete/route.ts`:

1. Explicitly deletes rows by `user_id` from `sorlio_feedback`,
   `sorlio_research_prompt_responses`, and `sorlio_analytics_events`. These use
   `on delete set null`, so they would otherwise survive as orphans.
2. Calls `auth.admin.deleteUser`, which cascades to `sorlio_user_data`,
   `sorlio_subscriptions`, and `sorlio_ai_usage` via their `on delete cascade`
   references.

Two deliberate exceptions, both worth being able to explain if asked:

- **`sorlio_android_beta_interest` is not deleted.** It is keyed by email, not by
  account, and holds its own unsubscribe token. Deleting the row would destroy
  the record that stops further email to that address. Readers unsubscribe via
  the link in the email.
- **The Google Play subscription is not cancelled.** Google owns that billing
  relationship; the app tells the reader this and links to Play's subscription
  management. `src/components/DeleteAccountDialog.tsx`.

Local device data is untouched by account deletion by design — the app keeps
working as a guest afterwards, and the reader clears local data by clearing
storage or uninstalling. This is stated in the deletion dialog.

## Third parties that receive data

| Party | Receives | When |
| --- | --- | --- |
| Supabase | Account identity, synced learning data, entitlements, feedback, analytics rows | Only for a signed-in reader, or after analytics consent |
| Google Play | Purchase and subscription state | Only on a Premium purchase |
| OpenAI | The specific word, sentence, or article text an AI action needs | Only when the reader triggers an AI-backed action |
| Vercel | Standard request logs for hosting | Always (hosting) |
| Sentry | Error and crash diagnostics | Only if a DSN is configured |
| Resend | Beta confirmation email address | Only if beta email is enabled (off by default) |

None of these constitutes "sharing" in Play's sense — each is a processor acting
on Sorlio's behalf, not a party receiving data for its own purposes.
**VERIFY CURRENT GOOGLE PLAY REQUIREMENT:** confirm Play still draws the
processor/sharing distinction this way before answering the "shared" questions.
